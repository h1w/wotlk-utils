Учитывая ваши приоритеты (абсолютная безопасность, готовность к гибридным архитектурам и максимальная реалистичность), я разработаю стратегию, которая обходит технические ограничения (32-бит, невиртуальный фильтр) и фокусируется на надежности и скрытности.

Поскольку `dtQueryFilter` не является виртуальным в вашей сборке, мы **не можем** использовать динамическое изменение стоимости полигонов (`setAreaCost`) для avoidance. Это критическое ограничение. Вместо этого мы будем использовать **геометрическую валидацию пути** и **поведенческое руление**.

---

### 1. Обход враждебных NPC (Приоритет: Безопасность)

Так как мы не можем изменить стоимость полигонов на лету, мы используем подход **"Plan & Validate"** (Планируй и Проверяй).

#### a) Реализация Avoidance без изменения Filter
Вместо попытки заставить A* избегать зон через стоимость, мы строим путь по навмешу, а затем проверяем его на пересечение с сферами аггро.

**Алгоритм:**
1.  **Построение базового пути:** `dtNavMeshQuery::findPath` (игнорируя NPC).
2.  **Валидация сегментов:** Пройдитесь по всем сегментам прямого пути (`findStraightPath`). Для каждого отрезка проверьте расстояние до всех враждебных NPC.
3.  **Обнаружение угрозы:** Если расстояние от отрезка до центра NPC < `AggroRadius + SafetyMargin`, путь считается **небезопасным**.
4.  **Локальный обход (Steering):**
    *   Не пересчитывайте глобальный путь сразу (это дорого).
    *   Вычислите касательную точку вокруг сферы аггро NPC.
    *   Вставьте эту точку как промежуточный вейпоинт.
    *   Отправьте бота к этой точке через CTM.

**Код валидации (C++):**
```cpp
bool IsPathSafe(const std::vector<float>& pathCoords, const std::vector<NPC>& enemies, float safetyMargin) {
    for (size_t i = 0; i < pathCoords.size() - 3; i += 3) {
        float* p1 = &pathCoords[i];
        float* p2 = &pathCoords[i + 3];
        
        for (const auto& npc : enemies) {
            if (!npc.IsHostile()) continue;
            
            float aggroRange = 20.0f + (npc.level - player.level);
            aggroRange = std::max(5.0f, std::min(45.0f, aggroRange));
            float safeRange = aggroRange + safetyMargin; // Например +5 ярдов

            if (DistanceToSegment(npc.pos, p1, p2) < safeRange) {
                return false; // Путь опасен
            }
        }
    }
    return true;
}
```

#### b) Safety Margin (Запас безопасности)
Учитывая приоритет безопасности:
*   **Тип:** Аддитивный (`+5` - `+10` ярдов). Мультипликативный опасен на высоких уровнях (может стать слишком огромным).
*   **Значение:** `AggroRadius + 7.0f`.
    *   *Почему 7?* Серверный тик 400ms. Пинг 100ms. Задержка реакции бота. Вам нужно буферное пространство, чтобы сервер не зарегистрировал аггро до того, как бот успеет повернуть.
*   **ThroughDanger:** Если безопасного пути не существует (например, узкий проход между двумя элитами):
    *   **Решение:** Бот **не должен** идти. Он должен ждать, пока один из NPC не уйдет (патрулирование), или использовать предмет невидимости/маскировки.
    *   *Профессиональные боты:* HonorBuddy/WRobot обычно приостанавливают движение и ждут 5-10 секунд, затем репатят. Не идите через опасность насильно.

#### c) Движущиеся цели (Патрули)
*   **Кэширование:** Не проверяйте всех NPC каждый кадр.
*   **Частота:** Обновляйте список угроз каждые **200-300 мс**.
*   **Предсказание:** Если NPC движется, экстраполируйте его позицию на 1 секунду вперед (`Pos + Velocity * 1.0s`). Проверяйте коллизию с будущей позицией.

### 2. Навигация на большие расстояния (Континенты)

Загрузка всей карты невозможна в 32-битном процессе (лимит ~2GB RAM, навмеш Восточных Королевств весит гигабайты).

#### a) Гибридная архитектура (World Graph + Local Navmesh)
Это стандарт индустрии для MMO ботов.
1.  **Глобальный граф (World Graph):**
    *   Создайте вручную или сгенерируйте稀疏ный граф ключевых точек: Города, ГР (Flight Masters), Порталы, Границы зон, Мосты.
    *   Ребра графа содержат тип перехода: `Walk`, `Flight`, `Teleport`, `Boat`.
    *   **Алгоритм:** A* на этом графе дает последовательность зон и ключевых точек (Stormwind -> Flight Master -> Ironforge).
2.  **Локальная навигация (Detour):**
    *   Используется только для отрезка между текущей позицией и следующей точкой глобального графа.
    *   Как только отрезок пройден, загружается следующая зона.

#### b) Стриминг тайлов (Tile Streaming)
*   **Радиус загрузки:** 5x5 тайлов вокруг игрока.
    *   1 тайл = 533 ярда. 5x5 = ~2600 ярдов видимости. Этого достаточно для реакции.
*   **Управление памятью:**
    *   При движении проверяйте индекс тайла игрока.
    *   Если игрок входит в новый "чанк" тайлов (например, сместился на 2 тайла), запускайте асинхронную загрузку новых и выгрузку старых.
    *   **Важно:** Никогда не удаляйте тайл (`removeTile`), если он используется активным запросом `dtNavMeshQuery`. Сначала отмените запрос или дождитесь его завершения.
*   **TrinityCore PathGenerator:** Они загружают тайлы по мере необходимости для конкретного пути. Для бота лучше держать буфер вокруг игрока, так как цель может измениться в любой момент.

#### c) Переходы между зонами
*   Навмеш часто обрывается на границах зон.
*   **Решение:** В World Graph добавьте "Portal Link".
    *   Node A (конец зоны А) -> Teleport Action -> Node B (начало зоны Б).
    *   Бот должен знать координаты триггеров загрузки (loading screens).

### 3. Алгоритмы движения (ClickToMove + Реализм)

CTM в WoW 3.3.5 работает путем отправки пакета `CMSG_MOVE_SET_FACING` и `CMSG_MOVE_MOVE_TO`.

#### a) Сглаживание пути (Path Smoothing)
`dtFindStraightPath` (Funnel Algorithm) уже дает оптимальные углы. Но для CTM нужно больше:
*   **Lookahead Point:** Не отправляйте бота в следующую вершину полигона напрямую. Отправляйте его в точку на пути, отстоящую на **10-15 ярдов** вперед.
    *   *Почему:* Это предотвращает "дергание" на поворотах. Бот начинает поворачивать заранее.
*   **Прибытие (Arrival Threshold):**
    *   Для путешествий: 3.0 ярда (считаем, что достиг, если ближе).
    *   Для точных действий (лут, NPC): 0.5 ярда.
    *   *Осцилляция:* Если бот дергается у точки, увеличьте порог или добавьте гистерезис (достиг = < 3 ярда, стоп = < 1 ярд).

#### b) Детекция застревания (Stuck Detection)
*   **Логика:** Сохраняйте позицию `LastPos` и время `LastMoveTime`.
*   **Проверка:** Каждые 500 мс. Если `Distance(CurrentPos, LastPos) < 0.5` за последние 2 секунды -> **Stuck**.
*   **Восстановление:**
    1.  Прыжок (Jump) + Движение назад (Backward) на 1 секунду.
    2.  Если не помогло -> Репатинг (поиск пути с учетом текущей позиции как старта).
    3.  Если не помогло -> Телепорт в ближайшую безопасную точку ( Hearthstone или waypoint).

#### c) Частота репатинга
*   **Путешествие:** Только если путь заблокирован (динамическое препятствие) или каждые 30 секунд (профилактика).
*   **Бой/Опасность:** Каждые 1-2 секунды или при изменении позиции цели > 5 ярдов.
*   **Осцилляция:** Если репатинг происходит слишком часто ( > 5 раз в 10 секунд), включите "Cooldown" на репатинг (3 секунды) и используйте локальное руление (steering) вместо перестройки пути.

### 4. Продвинутые алгоритмы и Архитектура

#### a) Поведенческое дерево (Behavior Tree)
Не используйте простой конечный автомат (FSM). Используйте Дерево Поведения для гибкости.
*   **Root**
    *   **Sequence** (Путешествие)
        *   CheckPathSafety
        *   MoveToWaypoint
        *   HandleTransport
    *   **Selector** (Реакция)
        *   CombatIfAggro
        *   AvoidEliteIfClose
        *   ResumePath

#### b) Theta* / Any-Angle
На навмеше Detour это избыточно. Funnel Algorithm (`findStraightPath`) дает результат, близкий к Theta*, но быстрее. Не тратьте CPU на Theta* поверх Detour.

#### c) Потенциальные поля (Potential Fields)
Используйте **только для финальных 5-10 ярдов**.
*   Навмеш ведет к общей цели.
*   Когда цель близко (<10 ярдов), включите векторное поле отталкивания от NPC и притяжения к цели. Это даст очень плавное огибание без пересчета пути.

### 5. Технические детали Detour (32-bit)

#### a) Node Pool (maxNodes = 65535)
*   Этого достаточно для локального пути (в пределах 5x5 тайлов).
*   **DT_OUT_OF_NODES:** Возникает, если вы пытаетесь найти путь через слишком сложную геометрию (например, лабиринт) или загрузили слишком много тайлов, увеличив пространство поиска.
*   **Решение:** Ограничьте `maxSearchDepth` в `dtQueryFilter` или разбивайте длинный путь на сегменты (через промежуточные вейпоинты).

#### b) Управление тайлами (Tile Management)
*   **Безопасность:** `dtNavMesh::removeTile` инвалидирует все `dtPolyRef`, связанные с этим тайлом.
*   **Правило:** Перед выгрузкой тайла убедитесь, что `dtNavMeshQuery` не использует полигоны из этого тайла.
*   **Стриминг:**
    1.  Вычислите нужные тайлы (Grid 5x5).
    2.  Сравните с загруженными.
    3.  В очередь на выгрузку -> тайлы за пределами 7x7.
    4.  В очередь на загрузку -> тайлы внутри 5x5, которых нет в памяти.
    5.  Выполняйте загрузку в отдельном потоке, но применяйте `addTile` в основном потоке (Detour не потокобезопасен по умолчанию).

#### c) Конфигурация
*   Используйте `DT_FINDPATH_ANY_ANGLE` (если доступно в вашей версии Detour) для более прямых путей.
*   Включите `detailMesh` для точного определения высоты (Z), чтобы бот не летал над землей и не проваливался.

### 6. Анти-детекшн (Human-like Movement)

Это критически важно для 3.3.5a, где Warden сканирует память и поведение.

#### a) Шум в движении (Trajectory Noise)
*   **Проблема:** Боты ходят по идеально прямым линиям между вейпоинтами.
*   **Решение:** Добавьте шум Перлина (Perlin Noise) или случайное отклонение к целевой точке CTM.
    *   Отклонение: ±0.5 - 1.5 ярда в сторону от идеальной линии.
    *   Частота обновления шума: каждые 0.5 секунды.
    *   Это создаст эффект "виляния", как у живого игрока, который корректирует курс клавишами.

#### b) Скорость и ускорение
*   **Проблема:** Мгновенное достижение макс. скорости.
*   **Решение:** Эмулируйте физику.
    *   При старте движения: 0% -> 100% скорости за 0.5 - 1.0 секунду.
    *   При повороте > 45 градусов: снижайте скорость на 20-30%.
    *   Добавляйте случайные микро-паузы (100-300 мс) каждые 20-40 секунд движения.

#### c) Реакция на препятствия
*   **Проблема:** Мгновенный обход препятствия.
*   **Решение:** Добавьте задержку реакции (Reaction Delay).
    *   Если обнаружен NPC на пути, подождите 200-400 мс перед началом обхода. Человек сначала видит, потом реагирует.

#### d) Пакетный спам (CTM Packets)
*   Не отправляйте пакеты движения каждый тик (100ms).
*   Отправляйте только при изменении целевой точки или значительном отклонении.
*   Лимит: не более 5-10 пакетов движения в секунду.

### Итоговая рекомендация по архитектуре

1.  **Global Planner:** Граф зон и транспортных узлов (JSON или бинарный файл).
2.  **Local Planner:** Detour Navmesh (5x5 тайлов стриминг).
3.  **Safety Layer:** Геометрическая проверка отрезков пути против сфер NPC (радиус = аггро + 7 ярдов).
4.  **Movement Controller:**
    *   Принимает целевую точку от Local Planner.
    *   Добавляет шум (Noise).
    *   Эмулирует ускорение.
    *   Отправляет CTM пакеты с ограничением частоты.
5.  **Monitor:** Детекция застревания и репатинг по таймеру/событию.

Эта схема обеспечивает максимальную безопасность (за счет жесткой валидации), работает в ограничениях 32-бит (за счет стриминга и графа) и минимизирует риск детекта (за счет гуманизации движения).
