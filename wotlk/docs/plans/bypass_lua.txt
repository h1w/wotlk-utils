Техническая спецификация: Система эмуляции и обхода античита Warden (WoW 3.3.5a)

Данная спецификация описывает архитектуру и реализацию модуля эмуляции античита Warden для клиента World of Warcraft (Build 12340). Основная задача модуля — перехват входящих запросов от сервера, их анализ и формирование легитимных ответов («spoofing») для предотвращения обнаружения сторонних механизмов автоматизации.


--------------------------------------------------------------------------------


1. Перехват управления (Hooks) и точки входа

Для корректной работы эмулятора необходимо установить перехватчики в ключевых точках процесса WoW.exe. Использование стандартных точек останова INT3 (байт 0xCC) категорически запрещено, так как Warden сканирует память на их наличие. Рекомендуется использовать Inline JMP или VMT Hooking.

* SMSG_WARDEN_DATA (Opcode 0x2E8):
  * Адрес: 0x007DA850.
  * Условие: Перехват должен происходить строго после дешифрации пакета алгоритмом RC4.
  * Техническое требование: При перехвате необходимо сохранять состояние всех регистров, включая XMM и состояние с плавающей запятой (FPU), чтобы избежать рассинхронизации при обработке пакетов. Любая ошибка деконволюции приведет к немедленному разрыву соединения.
* FrameScript_Execute (0x00819210):
  * Адрес: 0x00819210.
  * Конвенция вызова: __cdecl.
  * Задача: Мониторинг и фильтрация Lua-скриптов, инициированных сервером через LUA_EVAL. Перехватчик обязан сохранять оригинальные байты функции (m_originalBytes) для обеспечения возможности вызова оригинального кода.


--------------------------------------------------------------------------------


2. Анализ протокола и структуры пакета

Warden является динамически загружаемым модулем. Синхронизация между клиентом и сервером базируется на ключе RC4 и начальном значении (Seed), передаваемом в первом пакете SMSG_WARDEN_DATA.

Структура входящего пакета:

Поле	Размер	Описание
Command ID	1 байт	Идентификатор команды (напр., 0x00 для проверок).
Payload Size	2 байта	Длина полезной нагрузки.
Check ID	1 байт	Тип конкретной проверки (напр., 0xF3 для MEM_CHECK).
Check Data	Вариативно	Параметры (адреса, смещения, длины, ожидаемые хеши).

Алгоритм парсинга: Модуль должен итерировать по пакету, извлекая ID каждой проверки. Для MEM_CHECK парсер извлекает 4 байта целевого адреса и 1 байт длины. Важно учитывать, что часто целью сканирования являются смещения Object Manager, используемого для отслеживания координат и состояния юнитов.

3. Техническая типология запросов (Check Types)

MEM_CHECK (ID 243 / 0xF3)

Запрос на вычисление хеша участка памяти. Это основной инструмент обнаружения патчей и хуков. Warden также использует этот тип для проверки "Trapped Memory" (ловушек) — сегментов памяти, которые выглядят как обычные игровые данные (напр., координаты игрока), но мониторятся на предмет внешнего доступа. Любое обращение к таким сегментам вне контекста WoW.exe приводит к флагу аккаунта.

PAGE_CHECK

Мониторинг атрибутов защиты страниц через VirtualProtect. Warden ищет страницы с правами PAGE_EXECUTE_READWRITE, что характерно для инъекций кода.

LUA_EVAL

Исполнение Lua-строки сервером. Используется для поиска глобальных переменных ботов или проверки "загрязнения" (tainting) окружения. Согласно "Honey Analogy", любой объект, затронутый кодом аддона или внешним вызовом, помечается как «липкий» (tainted).

Прочие проверки

* DRIVER_CHECK: Поиск загруженных драйверов по списку сигнатур (напр., инструментов анализа).
* MPQ_CHECK: Верификация целостности игровых архивов для поиска модифицированных моделей.

4. Алгоритмы противодействия и подмены (Spoofing)

Техника Shadow Copy для MEM_CHECK и Trapped Memory

Для обхода проверок памяти необходимо создать "чистый" контекст чтения:

1. Создание образа: Использовать CreateFileMapping и MapViewOfFile для создания в памяти точной копии оригинального WoW.exe прямо с диска.
2. Перенаправление: При получении запроса MEM_CHECK на адрес внутри сегмента кода или "Trapped Memory", эмулятор перенаправляет указатель чтения на соответствующее смещение в Shadow Copy.
3. Ответ: Вычисляется хеш от оригинальных байтов, что скрывает наличие хуков в основной памяти.

Spoofing для LUA_EVAL и Call Stack

Warden проверяет стек вызовов Lua на наличие адресов вне региона WoW.exe.

1. Контроль EIP/RIP: При выполнении LUA_EVAL необходимо убедиться, что указатель инструкций и стек вызовов выглядят так, будто они инициированы внутри .text сегмента игрового процесса.
2. Taint-Free окружение: Результаты выполнения Lua-кода должны подменяться (nil или false) для всех запросов о подозрительных переменных.

Защита от LCP (Longest Common Prefix)

Blizzard использует алгоритм LCP для анализа траекторий движения. У ботов, использующих Waypoints на навигационной сетке (NavMesh), значения LCP растут линейно со временем (за 10–45 минут).

* Решение: Реализовать модуль Waypoint Jitter. Необходимо добавлять рандомизированное смещение к каждой целевой точке и варьировать скорость поворота персонажа, имитируя человеческий ввод.

5. Архитектура программного модуля (C++)

Реализация эмулятора должна использовать динамическое вычисление смещений и скрытие собственных страниц памяти от PAGE_CHECK.

#include <vector>
#include <windows.h>

struct WardenContext {
    uint32_t serverSeed;
    struct {
        uint32_t i, j;
        uint8_t state[256];
    } rc4State;
};

class WardenMgr {
public:
    WardenMgr() : m_shadowCopy(nullptr) {}

    // Инициализация через CreateFileMapping для обхода детекта чтения
    bool InitializeShadowCopy(const char* exePath);

    void HandleSmsgWardenData(uint8_t* buffer, size_t length);

private:
    void ParseChecks(uint8_t* payload, size_t size);
    
    // Перенаправляет чтение с Trapped Memory на Shadow Copy
    void ProcessMemCheck(uint32_t address, uint8_t length);
    
    void SendResponsePacket(uint8_t* data, size_t size);

    WardenContext m_context;
    uint8_t* m_shadowCopy;
    std::vector<uint8_t> m_originalBytes; // Резерв для восстановления хуков
};


Принципы безопасности:

1. Скрытие модуля: Память самого эмулятора должна иметь стандартные атрибуты PAGE_READONLY или PAGE_READWRITE в моменты покоя.
2. Динамические смещения: Все вызовы функций WoW.exe (например, FrameScript_Execute) должны выполняться через вычисление BaseAddress + Offset во избежание статических сигнатур.
3. Синхронизация RC4: Любое отклонение в состоянии ключа приведет к дисконнекту, поэтому обработка пакета должна быть атомарной относительно потока сетевого трафика.
